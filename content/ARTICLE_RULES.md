# コラム作成ルール（自動作成・手動作成共通）

このファイルと `content/BLOG_PLAN.md` を読んでから作業します。`content/check_site.py` が通らない記事は公開待ちにしません。

## 1. 内容のルール（守れない場合は作らずに止める）

- 行政の制度・補助金・労災統計は、作成日時点の公式資料（厚生労働省、各労働局・労働基準監督署、経済産業省、健康経営優良法人の公式サイトなど）で確認する。確認できない制度情報は書かない。
- 数値には、対象集団・年度・条件を添える（例：「令和7年の休業4日以上の死傷者のうち」）。出典は主張の近くにリンクし、末尾の「出典・参考」にもまとめる。
- 補助金記事は、対象年度、確認日、申請期間、公式情報へのリンクを書く。採択・交付を保証しない。申請代行はしていない。
- 医学的な効果を書くときは、ガイドライン・系統的レビュー・原著論文などで確認できた範囲にとどめる。
- 「治る」「完治」「改善します」「必ず防げる」「再発しない」などの断定や効果の保証は使わない。本サービスは医療行為ではなく予防のための支援であること、痛みやしびれなどの症状がある場合は医療機関に相談することを書く。
- 企業支援の実績、顧客の声、改善率、事例を作らない。説明用の例・見本は「例」「見本」と明記する。
- 著者は実際の体制どおりに書く。AIで作成した記事は「作成：プライズネス健康経営サポート」とし、`article-note` でAIを活用したことを示す。人（理学療法士 成田悟志）が内容を確認した記事だけ、オーナーの指示を受けて「監修」を表示する。
- 料金は `plans.html` と同じ表記だけを使う（例：単発セミナー55,000円〜）。新しい料金や条件を作らない。
- 他サイトの文章を転載しない。根拠を踏まえて独自に説明する。
- 文字数を満たすための引き延ばしはしない。担当者が「自社で何をすればよいか」「依頼すると何をしてもらえるか」が分かることを優先する。

## 2. 記事の構成（検索意図に合わせて調整してよい）

1. 内容が具体的に分かるタイトル（`title` は「…｜札幌の健康経営サポート」で終える）
2. リード文で読者の疑問に直接答える短い結論
3. 「この記事の要点」（`article-number-list`、3〜4項目）
4. 「この記事が役立つ方」
5. 課題の背景と根拠（出典リンク付き）
6. 職場で実施できる具体策（担当者が実際に尋ねる質問を見出しにする）
7. 表（`table-wrap` + `article-table`）やチェックリスト（`check-points`）
8. 依頼すると何をしてもらえるか（`/services`、`/plans` へのリンク）
9. CTA（`/contact` 主、`/workplace-low-back-pain-check`、`/services`）
10. よくある質問（5問。表示と FAQPage 構造化データを同じ文面にする）
11. 関連する記事（2〜3本＋ `/blog`）
12. `article-note`（AI作成の明記）と「出典・参考」

## 3. HTMLの作り方

- 直近に作られた記事（`blog/index.html` の一覧の一番上）をテンプレートとしてコピーし、構造とクラスを変えない。
- ファイルは `blog/<slug>.html`。slug は英小文字・数字・ハイフンのみ、既存と重複させない。
- `canonical` と `og:url` は `https://priseness-health-support.vercel.app/blog/<slug>`。
- `og:image` はリポジトリ直下の `*-og.jpg`、本文の画像は `*.webp`（`width="1600" height="900"`、記事の最初の画像は遅延読み込みにしない）。
- 構造化データ：Article（author は Organization「プライズネス健康経営サポート」）、FAQPage、BreadcrumbList。
- パンくず（`breadcrumb`）、公開日・更新日、GA4（G-EWVE5W7WNE）と Vercel Web Analytics のタグを入れる。
- 既存記事の大幅更新では、`dateModified` と表示の「更新日」を更新日にする。公開日は変えない。内容を変えない場合は日付を変えない。

## 4. サイト側の更新

- `blog/index.html`：一覧の一番上にカードを追加し、ItemList の先頭にも追加して position を振り直す。
- `index.html`：新着情報（`news-grid`）の一番上にカードを追加し、3件だけ残す。
- `sitemap.xml`：新しいURLを追加。`lastmod` は内容を変えたページだけ更新する（全ページを書き換えない）。
- `content/BLOG_PLAN.md`：状態と slug、主な出典を更新する。
- `content/RUN_LOG.md`：実行日時、選んだテーマ、結果、チェック結果を1行追記する。

## 5. 公開の流れ

- 公開待ちのプルリクエストは常に1つにまとめる。`content/` で始まるブランチの未マージのPRがあれば、そのブランチに追加コミットし、PRの本文に記事を追記する。なければ main から `content/blog-YYYYMMDD` を作る。
- オーナーがPRを確認してマージすると、Vercel が自動で公開する。
- `python3 content/check_site.py` が失敗した場合、または出典が確認できない場合は、PRに含めない。GitHub の Issue「コラム自動作成の停止ログ」（なければ作成）に、日時・テーマ・理由をコメントで残す。
